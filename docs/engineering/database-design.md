# Database Design

PostgreSQL 16+ is the single source of truth ([ADR-003](../adr/003-postgresql-source-of-truth.md)). The schema is managed with Drizzle ORM and drizzle-kit SQL migrations ([technical-stack.md §3.3](technical-stack.md#33-drizzle--nestjs--better-auth)).

ER overview: [diagrams.md §9](../architecture/diagrams.md#9-database-er-diagram).

---

## 1. Conventions

| Convention | Rule |
|---|---|
| Primary keys | `id text` holding a **prefixed ULID** (`wks_01J…`, `ses_…`, `act_…`). Sortable, URL-safe, and the type is visible in logs. Generated in the app |
| Timestamps | `created_at`, `updated_at timestamptz not null default now()`. All instants are `timestamptz` (UTC) |
| Local times | `local_time time` / `local_date date` with the owning workshop's `timezone text` (IANA) |
| Optimistic locking | `version integer not null default 1` on admin-editable aggregates. It increments on every update |
| Soft delete | `deleted_at timestamptz` only on `participants`, `workshops`, `automation_workflows`. Execution tables are never deleted, only archived |
| Enums | Postgres `text` + `CHECK` constraints (easier migrations than native enums), with Zod mirrors in `@wos/contracts` |
| JSON | `jsonb` for typed config, validated by Zod on write. Every jsonb column has a `*_schema_version int` where its shape may evolve |
| Money | Not stored (payment status only) |
| Naming | snake_case, plural table names |

## 2. Status enums (shared)

```text
workshop_status        : draft | ready | publishing | published | published_with_issues | in_progress | completed | cancelled | archived
automation_state       : inactive | active | paused | stopped
execution_status       : pending | waiting | scheduled | running | retrying | succeeded | succeeded_with_errors
                         | failed | skipped | cancelled | paused | blocked | awaiting_confirmation
                         | needs_attention | accepted
status_reason          : superseded | stopped | emergency_stopped | paused_by_admin | dependency_unsatisfied
                         | dependency_critical_failed | capability_missing | deadline_exceeded | missed_window
                         | no_consent | invalid_recipient | frequency_capped | quiet_hours | unknown_outcome
                         | auth_error | manual_override | skipped_by_admin | rehearsal_redirected
                         (column `status_reason` on every execution table; see playbook G-04)
registration_status    : pending | needs_review | pending_payment | confirmed | waitlisted | cancelled | refunded
payment_status         : not_required | unpaid | pending | paid | refunded | failed | unknown
completion_status      : not_evaluated | completed | not_completed | manual_review | exempt
integration_status     : disconnected | connected | degraded | auth_error | disabled
sync_status            : pending | synced | drifted | failed | not_applicable
```

`accepted` = an async provider acknowledged the request, and final delivery status is pending a callback.

## 4. Relationships summary

- Workshop 1–N Days 1–N Sessions. Workshop 1–N Activities (optionally tied to a day/session).
- Activity N–N Activity via `activity_dependencies` (DAG).
- Activity 1–N Activity runs 1–N Action executions 1–N Action attempts.
- Workflow 1–N Versions 1–N Executions 1–N Step executions 1–N Action executions.
- Participant 1–N Registrations N–1 Workshop. Registration 1–N attendance records. Registration × Session → session_attendance.
- Integration 1–N credentials, comms triggers, sheet bindings, calendar links, zoom sessions.

## 5. Indexes

Hot paths and their supporting indexes:

| Query | Index |
|---|---|
| Sweeper: overdue scheduled runs | `activity_runs (scheduled_for) WHERE status='scheduled'` |
| Arming cron: activities entering horizon | `timeline_activities (scheduled_for) WHERE enabled AND current_status IN ('pending','waiting')` |
| Control Center: workshop activities by time | `timeline_activities (workshop_id, scheduled_for)` |
| Execution Monitor: problems | `action_executions (status) WHERE status IN ('failed','needs_attention','retrying')` + `(workshop_id, status, created_at desc)` |
| Participant comms history | `action_executions (target_type, target_id)` |
| Outbox relay | `outbox_events (next_attempt_at) WHERE status='pending'` |
| Webhook dedupe | `webhook_events (dedupe_key) UNIQUE` |
| Participant dedupe | partial uniques on `email_normalized`, `phone_e164` |
| Trigger matching | `workflow_triggers (event_name)` |
| Audit by entity | `audit_logs (entity_type, entity_id, occurred_at desc)` |

## 6. Integrity rules implemented in the database

- `CHECK` that exactly one of `activity_run_id` / `workflow_step_execution_id` is set on `action_executions`.
- Trigger forbidding UPDATE/DELETE on `workflow_versions` (definition) and on `audit_logs`.
- Trigger ensuring `activity_dependencies` endpoints belong to the same workshop.
- `ON DELETE RESTRICT` on all FKs from execution tables, so history is never cascaded away. Workshops are soft-deleted.
- Unique constraints listed above are the **last line of defense** for idempotency.

## 7. Migrations and data lifecycle

- drizzle-kit `generate` → reviewed SQL → applied by a CI job before app rollout. Migrations must be **backward compatible with the previous app version** (expand/contract). Never rename a column in a single release.
- Archival job (monthly): move `action_attempts` older than 6 months and terminal executions older than 24 months to R2 as compressed JSONL, then delete them **[CONFIRM Q15]**.
- Seed data: default roles, app settings, built-in workflow templates (registration, reminders, completion).

## 8. Sizing estimate

Assumptions: 10 workshops/month, 500 registrations each, 40 activities each, 15 participant-scoped comms activities.

- `action_executions`: ~10 × 500 × 15 × 2 channels = **150k/month**. `action_attempts`: ~1.2× that.
- `attendance_records`: 10 × 6 sessions × 500 × ~1.5 joins = 45k/month.
- Total growth well under 1 GB/month including indexes. A small managed Postgres instance (2 vCPU / 4–8 GB) is ample.
